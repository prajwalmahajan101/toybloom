# M9 — Local observability stack + Bloom gauges

**Date:** 2026-09-05 · **Branch:** feat/phase4-observability · **Base SHA:** 7a5ccab

## Goal
Deliver the backend half of ADR 0005: a discrete-container LGTM stack that
receives the app's OTLP stream and makes it visible in Grafana — RED metrics
with trace exemplars, distributed traces, correlated logs — all from one
`docker compose up`. Also close the fill-ratio / estimated-FPP gauges deferred
from M8 (ADR 0007), so the Bloom dashboard shows real per-filter saturation.

## What was done
- **`pkg/bloom/estimate.go`** (new): pure `Filter.FillRatio()` (Σfill ÷ Σcapacity)
  and `Filter.EstimatedFPP()` (per-stage `(1-e^(-k·fill/m))^k`, compounded), plus
  `ListFilters` wrapping the existing `bf:registry` set. No OTel in `pkg/`.
- **Fill-counter read fix**: `Add` incremented the atomic `:fill` counter but
  `Load` rebuilt `Stage.Fill` from the never-updated hash seed, so every fresh
  `Load` (stats endpoint + gauges) read 0. Added `Get` to the `BitStore`
  interface (+ `ValkeyStore`, `MemStore`); `Load` now reads each stage's `:fill`
  counter. Fixes `GET /stats` too. (ADR 0008 #3.)
- **`internal/obs/metrics.go`**: four observable gauges —
  `toybloom.filter.fill_ratio`, `…estimated_fpp`, `…items` (per-filter, labelled),
  and `…count` (scalar, no label) — plus `ObserveFilters`, which registers a
  multi-instrument callback fed by a caller-supplied collect func returning a
  `FilterObservation{Count, Samples}`.
- **`internal/service`**: `FilterSamples` enumerates live filters, reports the
  true pre-cap `Count`, then (capped) loads each and computes fill/FPP/items,
  skipping Load-misses. Added to the interface.
- **Dashboards**: Bloom adds "Live filters", "Total items (current)", and
  "Items per filter"; RED adds "p99 latency by request type (method + route)".
- **`internal/core/config`**: `OBS_MAX_FILTER_GAUGES` (default 100).
- **`cmd/server/main.go`**: pass the cap to `service.New`; register
  `inst.ObserveFilters(svc.FilterSamples)`.
- **`deploy/`** (new): `collector/config.yaml` (OTLP in → Prometheus/Tempo/Loki
  out; OpenMetrics exemplars), `prometheus/prometheus.yml`, `tempo/tempo.yaml`,
  `loki/loki.yaml`, and `grafana/` (datasources with Prom→Tempo exemplar link and
  Loki→Tempo derived field; RED + Bloom dashboards).
- **`Dockerfile`** (new): multi-stage static build → distroless-nonroot.
- **`docker-compose.yml`** (new): app + valkey + collector + prometheus + tempo +
  loki + grafana, single file, discrete services.
- **Docs**: ADR 0008 (per-filter gauge cap, amends 0007) + index; ROADMAP M9 ☑.

## Decisions & why
- **Discrete containers over `grafana/otel-lgtm`** — the ADRs specify a
  per-component `deploy/` layout, and the seams (OTLP→Prometheus bridge, exemplar
  storage, provisioned datasources) are the point; the all-in-one hides them.
- **Per-filter gauges with a bounded cap** — the one label the gauges need,
  admitted narrowly against ADR 0007 #2 and bounded by `OBS_MAX_FILTER_GAUGES`.
  Recorded in **ADR 0008**.
- **Reuse `bf:registry`** — no second registry to keep in sync; the gauge
  callback reads the same set `New`/`Drop` already maintain.

## Verification
- `go build/vet/test ./...` green; new unit tests for `FillRatio`/`EstimatedFPP`
  (hand-checked table) and `FilterSamples` (cap truncation, non-zero fill).
- `docker compose config` valid.
- Full-stack `docker compose up --build`, drove the create/add/exists flow, and
  confirmed each signal live against the backends:
  - **Metrics** — Prometheus has `toybloom_filter_fill_ratio{filter="emails"}=0.05`
    (= 50/1000) and `estimated_fpp=2.22e-15` (matches the formula by hand),
    RED counters, and a non-NaN p99.
  - **Traces** — Tempo returns `toybloom` spans (`valkey.get`, service/handler).
  - **Logs** — Loki returns request logs with `trace_id`==`correlation_id`,
    `span_id`, `status`, `latency_ms` as labels (id unification per ADR 0007).
  - **Exemplars** — Prometheus stores exemplars carrying `trace_id`, linkable to
    the Tempo traces (the p99 → trace jump).
  - **Fill fix** — `GET /stats` now shows `fill: 50` on a fresh `Load` (was 0).

## Bring-up fixes (deploy/)
- **Loki ring:** switched the ring kvstore from `inmemory` to `memberlist` (single
  node). With `inmemory`, the query-scheduler ring stayed empty on the read path
  ("0 healthy replicas … 127.0.0.1:9095") and log queries failed even though
  ingestion worked; memberlist shares one ring across ingester + scheduler.

## Follow-ups
- Valkey op-latency panel is span-only today (no metric); would need Tempo's
  metrics-generator or a store-side histogram — deferred to M10.
- **Collector image pin:** `otel/opentelemetry-collector:0.160.0` (core distro).
  The planned contrib `0.116.0` image would not exec on this host (Docker 29.5.1:
  `exec /otelcol-contrib: no such file or directory` for that image range; `latest`
  and older tags run fine). The config uses only core components, so the core
  distro is the correct, lighter choice regardless. On 0.160 the config draws two
  harmless deprecation warnings (`otlp`/`otlphttp` exporter aliases,
  `resource_to_telemetry_conversion`) — left as-is for portability to older
  collectors where the newer names don't exist.
