# M8 — OpenTelemetry instrumentation

**Date:** 2026-09-04 · **Branch:** feat/phase4-observability · **Base SHA:** 7a5ccab

## Goal
Reconcile the app with ADR 0005 by replacing the partial, split telemetry
pipeline (prometheus-client `/metrics` scrape + standalone UUID `correlation_id`)
with real OpenTelemetry SDK instrumentation: one OTLP stream of traces, metrics,
and logs, correlated by a single id. App-side only — the LGTM docker stack is M9.

## What was done
- **`internal/obs`** (new): `provider.go` builds the resource + three SDK providers
  (trace/metric/log) behind an exporter-mode switch (`otlp` | `stdout` | `none`),
  registers the OTel globals + W3C propagator, and exposes one `Shutdown` that
  flushes all signals. `metrics.go` declares the RED histogram + bloom counters.
  `logger.go` bridges slog onto the log provider via `otelslog`.
- **`internal/api`**: deleted `metrics.go` (prometheus registry + `/metrics`
  route). Added `otelgin` as the outermost middleware and an OTel `HTTPMetrics`
  middleware. `CorrelationID` now derives the id from the active span's trace id;
  `RequestLogger` switched `Info` → `InfoContext` so the otelslog bridge stamps
  trace context. `NewRouter` threads `serviceName` + `*obs.Instruments`.
- **`internal/service`**: each `FilterService` method wrapped in a span
  (`RecordError`/`SetStatus` on failure) plus an op counter; `Add` records items.
- **`pkg/store/valkey.go`**: each Valkey op wrapped in a client span via the
  global tracer (no-op-safe), through a shared `startSpan` helper. `pkg/bloom`
  untouched (stays pure).
- **`internal/core/config`**: added `ServiceName` (`OTEL_SERVICE_NAME`) and
  `ObsExporter` (`OBS_EXPORTER`); endpoint/sampler left to standard `OTEL_*` env.
- **`cmd/server/main.go`**: `obs.Setup` first, logger built from the providers,
  instruments injected; shutdown drains the HTTP server then flushes telemetry.
- **Deps**: added the OTel SDK, OTLP + stdout exporters, `otelgin`, and the
  `otelslog` bridge; removed `prometheus/client_golang` entirely.
- **Docs**: ADR 0007 (instrumentation boundaries); ROADMAP M8 ☑ and M4–M7
  checkboxes reconciled to reality.

## Decisions & why
- **`pkg/` stays OTel-free except Valkey spans; metrics at the service layer;
  `correlation_id` unified onto `trace_id`; standard `OTEL_*` autoconfig** — the
  four boundary calls, recorded in **ADR 0007**. Rationale there.
- **Exporter-mode switch** — `OBS_EXPORTER=stdout` makes the whole pipeline
  verifiable before the M9 Collector exists; `none` disables the SDK for tests /
  Collector-less runs. Keeps M8 self-contained.
- **`InfoContext` over `Info`** — the otelslog bridge stamps `trace_id`/`span_id`
  only when a context is supplied; using the plain method silently drops the
  correlation. A one-line change with an easy-to-miss failure mode.

## Verification
- `go build ./... && go vet ./...` — clean. `go test ./internal/... ./pkg/bloom/...`
  — green (Valkey testcontainers suite excluded; needs Docker).
- New `internal/api/otel_test.go` (in-memory exporters): asserts a server span
  with a child `FilterService.Create` span in the same trace, the
  `http.server.request.duration` histogram tagged with `http.route`, and a log
  record stamped with the request's `trace_id`. Passing.
- **Full-chain stdout smoke** (real Valkey container, `OBS_EXPORTER=stdout`): create
  → add → check emitted server spans (`POST /v1/filters`, …), service spans
  (`FilterService.Create/Add/Exists`), Valkey spans (`setbit, getbit, hset,
  hgetall, incr, sadd`), the RED histogram, `toybloom.filter.items_added` /
  `.operations`, and request logs carrying a live `TraceID`. `GET /metrics` → 404.
