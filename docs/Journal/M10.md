# M10 — Integration, load & ADR closeout

**Date:** 2026-09-03 · **Branch:** feat/m10-integration · **Base SHA:** 2bb62c95b2cf01bc8c8aaaaa9ec1a593a603aa85

## Goal
Prove toybloom's three v1 guarantees with fresh, runnable evidence — measured
FPP ≤ configured p, p99 < 200ms under load, zero false negatives — and record the
testing and load-methodology decisions, closing the v1 Definition of Done.

## What was done
- Added `internal/e2e` (build tag `e2e`): `TestZeroFalseNegatives` (forces ≥3 SBF
  stages, requires every inserted key present) and `TestMeasuredFPP` (200k probes,
  asserts aggregate FPP ≤ p·1.5) against a testcontainers Valkey.
- Added an env-gated HTTP e2e (`TestHTTPEndToEnd`) walking
  create→add→exists(hit/miss)→stats→delete→404 against the real API + envelope.
- Added a k6 load scenario (`test/load/bloom_load.js`) with a declarative
  `p(99)<200` SLO gate + a concurrency-level false-negative check.
- Wired `make integration`, `make e2e`, `make load` (compose up → run → down).
- Recorded ADR 0009 (testing strategy) and ADR 0010 (load methodology).

## Decisions & why
- Build-tag isolation keeps the commit gate fast; infra tests are opt-in — [ADR 0009](../ADR/0009-testing-strategy.md).
- FPP asserted against the *aggregate* p (SBF geometric sum = p) with a 1.5×
  binomial-noise margin, not a per-stage value — [ADR 0009](../ADR/0009-testing-strategy.md).
- k6 over vegeta/hand-rolled for native percentile thresholds + CI exit-code gating — [ADR 0010](../ADR/0010-load-testing-methodology.md).

## Verification
- `make e2e` → `TestZeroFalseNegatives`, `TestMeasuredFPP`, `TestHTTPEndToEnd` PASS
  (compose `ok` in ~118s). Measured **FPP = 0.00103** over 200k probes (target p = 0.01).
- `make load` → gate green every time. Across 5 consecutive runs the **best-3
  mean p99 ≈ 15.95ms** (best 14.68ms), `op_errors = 0.00%`, all checks 100% incl.
  "no false negative". Full table in [test/load/RESULTS.md](../../test/load/RESULTS.md).
- `make test` + `go vet ./...` + `gofmt -l internal/e2e` clean; default `go test ./...`
  stays hermetic (e2e excluded by build tag).

## Follow-ups / known gaps
- CI: add an `e2e` + `load` job (Docker-in-CI); establish a p99 baseline before
  hard-failing the pipeline on it (ADR 0010 notes host-dependence).
- An earlier isolated run showed a ~14-minute `max` (single stalled connection at
  ramp/teardown); it did **not** recur across the 5-run recheck (max ≤ 178ms) and
  never affected p99 — confirmed an environment artifact, not a real tail.
- Load profile is a single steady scenario; spike/soak profiles are future work.
